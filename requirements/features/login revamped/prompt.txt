### 🔐 2. MULTI-SESSION ISOLATION & ROUTE SECURITY
*   **Session Independence:** If a patient dashboard is active and an administrator authenticates on the same system or local network node, sessions must remain isolated. Roles must work independently (`/medi-clinic/dashboard` vs `/medi-clinic`) without token overrides, cookie bleed, or session eviction.
*   **Registration Guardrails:** Public patient registration actions (`New Patient? Create an account`) route to `/clinic-register` and are entirely hidden from routes starting with `/medi-clinic/dashboard` or `/medi-clinic/doctors`. 
*   **Lazy Onboarding Profile Queue:** New users register credentials first. Upon initial authentication, they are intercepted by a profile-completion step. Profiles sit in an administrative review queue (`clinic-patient-access-requests.sql`) before accessing application layouts.
